# 阶段 2 实机记录：界面可读性与字体颜色

日期：2026-10-12（Asia/Taipei），官方 `OpenAI.Codex` 版本
`26.1007.2314.0`，测试会话经验证使用本机回环 CDP 端口 `9335`。

已复现：Codex 浅色主题的正文计算色为 `rgb(24, 51, 79)`，旧注入层
强制使用 `rgba(20, 22, 26, 0.72)` 暗色背板，正文几乎不可读。
将背板改为按主题选择后，真实窗口截图
`../work/audit/codex-live-2026-10-12T12-43-30.650Z.png`
显示正文和侧栏可读，壁纸仍在背后播放。该截图是临时等效样式预览；
正式代码已包含同样规则，现有守护进程仍需重启加载。

已验证失败方案：将 `127.0.0.1` 控制网页作为 iframe 嵌入 Codex，
虽然 iframe 触发 `load` 事件，但真实窗口显示“该内容被屏蔽了”。
Codex renderer 对本地控制服务的 `fetch`（含 `no-cors`）也返回
`TypeError: Failed to fetch`。测试 iframe 已移除。

替代实现：通过 CDP `Runtime.addBinding` 在已验证的 Codex 主页面和
GPTDaddy 守护进程之间传送限定的控制动作，不依赖本地网页嵌入。
短时实机验证脚本 `scripts/validate-inapp-panel.mjs` 使用只读动作，
真实窗口截图 `../work/audit/codex-inapp-panel-2026-10-12T12-54-07.816Z.png`
显示悬浮入口、首页状态“壁纸正在播放”，并成功读取 47 个壁纸项目。
测试脚本结束后移除了测试注入。四个页面和状态动作尚未逐项完成交互验收。

新增“字体颜色”：配置只接受 `#RRGGBB` 或 `null`（自动）；
Codex 内面板和浏览器控制页都有选择器，设置持久化到统一状态文件。
实机临时样式验证：一段正文从 `rgb(24, 51, 79)` 变为
`rgb(150, 55, 168)`；测试脚本移除覆盖后精确恢复为
`rgb(24, 51, 79)`。
正式代码在关闭壁纸时恢复原主题变量，不修改官方安装文件。

`npm run verify`：14 项自动测试通过。此结果不代表正常图标启动
自动壁纸已通过验收，也不代表 20 次对话切换、2 小时播放或
Windows 重启后的恢复测试已完成。
