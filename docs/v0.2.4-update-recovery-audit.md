# v0.2.4 Codex update recovery audit

The official Codex Windows package updated to `26.1013.4894.0`. Its ordinary
main process initially had no CDP argument, and the installed GPTDaddy daemon
was absent even though the wallpaper and native-recovery settings remained
enabled. The prior HKCU Run entry started the daemon only at sign-in; it could
not recover a daemon that exited later.

v0.2.4 adds a per-user scheduled watchdog. It checks the installed loopback
daemon every minute, starts only the installed GPTDaddy runner when needed,
and is removed by the GPTDaddy uninstaller. In the real Windows session, the
task ran with result `0`, restored the installed listener after it was absent,
and the installed controller reported version `0.2.4` while retaining the
existing wallpaper configuration. The installer was run in the default stable
per-user directory; its runtime script matched the built artifact.

The updated Codex accessibility tree did not reliably expose or execute its
old Quit menu while an active task was running. Package activation now has a
graceful `WM_CLOSE` fallback restricted to the verified official Codex main
window. It never force-terminates a Codex process, and a session that predates
a recovered daemon is still not restarted automatically. An activation attempt
during an active task did not exit Codex and was reported as incomplete, not
passed.

After that task ended and Codex was reopened, the real package process had
loopback CDP enabled and the installed `0.2.4` daemon reported the saved
wallpaper active with healthy playback. This verifies recovery in that live
session, not every future client update. The native loading splash remains
outside CDP styling until the renderer is attached.

After a later installer re-run, the renderer reported `document.hidden=true`
while Google Chrome was the foreground window. The video was paused in that
hidden state, so `playbackHealthy=false` was not counted as a visible-window
freeze. The earlier foreground playback check was healthy; this audit does not
claim continuous playback while the Codex window is hidden.

Release checks: 31 automated tests passed; the setup and portable runtime were
built and inspected for personal paths and the local API token. No Wallpaper
Engine media, private state, or chat screenshots are included in the packages.
